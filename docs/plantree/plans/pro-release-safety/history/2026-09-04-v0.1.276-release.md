# Pro v0.1.276 Release Retrospective

Date: 2026-09-04

## Outcome

Pro 最终发布 `0.1.276-pro.aa2d857c`，仅替换 app，迁移 259–264、数据库备份、二开标识、业务页面和独立 sidecar 验收通过。PostgreSQL、Redis、盈利 sidecar 和透明度 sidecar 未重建。

## Problems And Causes

1. `jq '.source.dirty // true'` 把合法的 `false` 当成 fallback，干净清单被误判为脏。
2. marker 正则通过 SSH 参数传递时包含 `|`，被远端 shell 解析成管道。
3. 盈利页面验收写死已废弃路径，应用已经成功切换后脚本仍报告失败。
4. shell 中失效的 `GITHUB_TOKEN` 覆盖了 GitHub CLI keyring 中的有效凭据。
5. 手工补全了错误的完整 commit SHA，工作流在 checkout 阶段失败；该次没有构建、推送或影响线上。
6. Pro 服务器没有持久可用的 GHCR 拉取凭据；GitHub CLI OAuth token 对镜像 blob 返回 403，临时 Docker 凭据虽可用但不应成为发布流程依赖。
7. 镜像拉取发生在远端发布目录创建和文件上传之后，拉取失败会留下不完整目录。
8. 远端步骤共用模糊错误出口，无法立即区分镜像、备份、切换、运行时、HTTP 和证据归档失败；有迁移时这会增加错误回退风险。
9. 当前 checkout 同时配置 fork `origin` 和上游 `upstream`，GitHub CLI 自动识别到了上游仓库；只固定 Git push 目标不足以保证 workflow 调度目标正确。

## Process Changes

- `make pro-image-dispatch` 从 Git 自动读取完整 HEAD，通过 `env -u GITHUB_TOKEN` 调用 GitHub CLI，并显式固定 `aether-shell/RootFlowTokenRouter` 仓库。
- `make pro-remote-check` 只执行镜像拉取、OCI 标签和 Pro Compose 归属检查；不得创建发布目录、备份或切换服务。
- `make pro-release` 在创建发布目录前强制复用同一远端预检；备份成功前不覆盖线上 override。
- 发布错误按 `image_preflight`、`artifact_upload`、`backup`、`switch_app`、`runtime_verify`、`http_verify` 和 `evidence_finalize` 分类。
- 盈利页面路径只从 `deploy/pro/customizations.yaml` 读取；SSH 中可能包含 shell 元字符的动态参数必须编码传输。
- Pro 服务器应配置专用、最小 `read:packages` 权限的 GHCR 部署凭据；凭据不写入仓库或发布证据。
